# MYDOS 教學：里程碑 5 — 計時器與時鐘

## 目標與成果

這個里程碑讓 MYDOS 有了「時間感」：知道開機多久了、現在幾點，也能睡一段時間再醒來。完成後版本號是 v0.5。

完成時你會看到：

- 狀態列右邊出現 `2026-11-26 14:05:03`，每秒跳一次
- 新指令 `TIME`、`DATE`（含星期幾）、`UPTIME`
- 核心多了 `timer_sleep_ms()`，之後 LIFE 動畫、程式的 `sleep()` 都靠它

| 檔案 | 硬體 | 用途 |
| --- | --- | --- |
| `timer.c` | PIT（8253/8254 計時晶片） | 每 10 ms 發一次 IRQ0，累計 tick |
| `rtc.c` | CMOS RTC（主機板上靠電池走的鐘） | 讀年月日時分秒 |

另外 `kprintf.c` 重構了一次，多了 `ksnprintf`（印到字串）和 `%-8s` 左對齊。

## PIT：可程式化計時器

PIT 裡面有一個以 **1,193,182 Hz** 跳動的計數器。這個怪數字來自 1981 年 IBM PC 的晶振頻率（14.31818 MHz ÷ 12），一直沿用到今天。

給它一個**除數** N，它每數 N 下就發一次 IRQ0：

```text
頻率 = 1193182 / N      →  要 100 Hz：N = 11931
```

設定只要三次 `outb`：

```c
outb(0x43, 0x36);              // 通道 0、先送低位元組再送高位元組、模式 3（方波）
outb(0x40, divisor & 0xFF);
outb(0x40, divisor >> 8);
irq_install(0, timer_irq);     // 里程碑 3 的 irq.c，順便解除 IRQ0 的遮蔽
```

`0x36` 拆開：`00`（通道 0）`11`（低位元組 + 高位元組）`011`（模式 3）`0`（二進位計數）。

中斷處理只做一件事：`ticks++`。`ticks` 要宣告成 `volatile`，因為它在中斷裡被改，主程式讀它時編譯器不能假設值沒變。

**為什麼選 100 Hz？** 頻率越高，計時越精細，但 CPU 花在處理中斷的時間也越多。100 Hz（10 ms 一次）是很多老系統的選擇，對 DOS 風格的系統綽綽有餘。

### 睡覺

```c
void timer_sleep_ms(uint64_t ms) {
    uint64_t end = ticks + (ms * TIMER_HZ + 999) / 1000;   // 無條件進位
    while (ticks < end)
        __asm__ volatile ("sti; hlt");
}
```

`hlt` 讓 CPU 睡到下一個中斷，最多 10 ms 就會被計時器叫醒一次，檢查時間到了沒。比起空轉的 `while (ticks < end) {}`，CPU 使用率從 100% 降到接近 0。

## RTC：讀主機板的時鐘

PIT 只知道「開機以來過了多久」，不知道現在幾點。真正的時間存在主機板的 **CMOS** 裡：一小塊靠鈕扣電池保存的記憶體，關機也不會忘。

讀法是先把暫存器編號寫到 port `0x70`，再從 `0x71` 讀值：

| 暫存器 | 內容 |
| --- | --- |
| `0x00` | 秒 |
| `0x02` | 分 |
| `0x04` | 時 |
| `0x07` | 日 |
| `0x08` | 月 |
| `0x09` | 年（只有後兩位） |
| `0x0A` | bit 7 = 正在更新 |
| `0x0B` | bit 1 = 24 小時制、bit 2 = 二進位（不是 BCD） |

### 三個陷阱

**1. 讀到一半換秒。** 從 23:59:59 跳到 00:00:00 的瞬間，可能讀到「秒是 00、時還是 23」。解法：等 `0x0A` 的更新旗標清掉再讀，而且**連讀兩次，兩次完全一樣才算數**。

**2. BCD 格式。** 大部分 RTC 用 BCD 存數字：`0x59` 代表 59（十六進位的每一位就是十進位的每一位），不是 89。轉換：

```c
static int bcd(int v) { return (v & 0x0F) + (v >> 4) * 10; }   // 0x59 → 9 + 50
```

**3. 12 小時制。** 如果 `0x0B` 的 bit 1 是 0，小時的 bit 7 代表下午。

### 時區

RTC 存的是「本地時間」還是 UTC，要看電腦怎麼設定（Windows 習慣存本地時間，Linux 習慣存 UTC）。QEMU 預設給 UTC，所以 `make run` 加了 `-rtc base=localtime`，讓 MYDOS 顯示台灣時間。

## 狀態列時鐘

計時器每 100 個 tick（一秒）讀一次 RTC，畫在狀態列右邊：

```c
static void timer_irq(void) {
    ticks++;
    if (ticks % TIMER_HZ == 0) update_clock();
}
```

這裡有個要注意的地方：**`update_clock` 是在中斷裡執行的**，主程式可能正畫字畫到一半。所以 `term_status_right()` 刻意寫成只碰狀態列那塊像素，不讀也不改游標 `(cx, cy)`、不送序列埠。兩邊碰的記憶體完全不重疊，就不會互相干擾。

`update_clock` 用新的 `ksnprintf` 把時間格式化成字串。這需要把 `kprintf` 重構：

```c
struct sink {
    void (*put)(struct sink *s, char c);   // 字元要送去哪
    char  *buf;
    size_t size, len;
};
```

格式化的邏輯只寫一次（`format()`），`kprintf` 的 sink 把字元送給 `term_putc`，`ksnprintf` 的 sink 把字元存進緩衝區。這是 C 語言裡模擬「介面」的常見手法：一個函式指標加一些狀態。

順便加上 `-` 旗標：`%-8s` 把字串印在 8 格寬的欄位靠左，`HELP` 指令的對齊就不用再手動補空白了。

## 星期幾

`DATE` 顯示星期幾，用的是 Sakamoto 公式：

```c
static const int k[] = { 0, 3, 2, 5, 0, 3, 5, 1, 4, 6, 2, 4 };
int y = year - (month < 3);                // 1、2 月算前一年的
int w = (y + y/4 - y/100 + y/400 + k[month - 1] + day) % 7;   // 0 = 星期日
```

`y/4 - y/100 + y/400` 是在算閏年的影響；`k[]` 是每個月 1 號相對的星期偏移。

## 測試

| 指令 | 預期 |
| --- | --- |
| 開機 | `[ ok ] PIT timer at 100 Hz, RTC clock`，狀態列右邊出現時間並每秒更新 |
| `TIME` | `Current time is 14:05:03`（跟 Windows 時鐘一致） |
| `DATE` | `Current date is Thu 2026-11-26` |
| `UPTIME` | 開機後經過的時間，跟手錶對得上 |

**常見問題：**

| 症狀 | 原因 |
| --- | --- |
| 時間差 8 小時 | QEMU 沒加 `-rtc base=localtime` |
| 時間是奇怪的數字（例如 89 分） | 忘了 BCD 轉換 |
| 狀態列時間不動 | IRQ0 沒解除遮蔽，或 `sti` 在 `timer_init` 之前就關掉了 |
| UPTIME 走太快／太慢 | 除數算錯；確認 `1193182 / 100` |
| 打字時畫面偶爾閃一個怪字 | 中斷裡的畫圖碰到了游標狀態 |
